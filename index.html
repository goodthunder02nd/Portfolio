BENCH NOTES // SOFTWARE & HARDWARE

Software on screen.
Hardware on the bench.

The handoff is where I get curious.

I study Computer Engineering at ICCT Colleges. What keeps me interested is seeing how a change in code meets the limits of the device it runs on.

On one side, I build Android utilities with Kotlin and Java and explore what the operating system allows. On the other, I build PCs, troubleshoot hardware, and install and configure Windows.

DarkScreen brings those interests together: a practical Android experiment that starts with a display and runs into an operating-system boundary. I like projects that leave me with something working and a more precise question than the one I started with.

FIELD NOTE // 01 Kotlin · Android OS

DarkScreen — Below the brightness floor

What if minimum brightness is still too bright? DarkScreen explores a Kotlin-powered system overlay to dim the display below Android’s native brightness floor. The interesting part is not just drawing the layer; it is working at the boundary set by Android’s overlay permission.
